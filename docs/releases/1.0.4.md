# Lucent 1.0.4

- **Settings has a Troubleshooting group with a Record frame generation switch, off by default.**
  - It sets `[FramePacing] FgRecorder` in `OptiScaler.ini` in place (`true` when on, `false` when switched off again) and nothing else, through the journal. It takes effect the next time XIV starts.
  - OptiScaler-FFXIV then writes what frame generation does to `fg-recordings` in the game folder, for a bug report: only while frame generation runs, up to 144 MB a play session, the last five sessions kept.
  - Unlike the Game patches switch it is not remembered: a Reset or a tier switch writes the tested setup again, with the recorder off. A content update keeps it, as it keeps any value in the player's own ini.
  - It needs content 2026.10.31 or newer, and it is disabled with the reason while XIV runs or when the ini has no `FgRecorder` line.
  - The mark key (`FgRecorderMarkKey`) has no control in Lucent; the OptiScaler overlay's Keybinds set it.
- **A Recordings row under the switch, shown while the folder exists.**
  - It has the session count, the size, Open folder and **Clear…**.
  - Clear asks first, then deletes only the recorder's own `fg-rec-*` files, and the folder once it is empty; any other file in it stays.
  - It needs XIV closed. Uninstall removes the recordings, as it has since content 2026.10.31.
- **Diagnostics and the bug report.**
  - Copy diagnostics has a `FG recorder:` line: on or off, then the session count and the newest session with its file count and size.
  - The GitHub issue template asks for the newest recording, zipped, when the problem is with frame generation.
- **Settings is tidied.**
  - The groups now run Launch XIV with, XIVLauncher, Updates, Game folder, Game patches, Troubleshooting, Storage, Danger zone.
  - "After a game patch" is now **Game patches**, and its switch carries the same Experimental tag as the Graphics step instead of "(experimental)" in its name.
  - Why changes wait (XIV running, a failed check for it, a missing game folder) is said once, at the top of the page, instead of under each group.
  - Reset setup's button is no longer styled as the page's main action.
  - The page's subtitle names everything it holds.
- **Nothing else changes.** The setup Lucent writes and every other screen are as they were in 1.0.3. No new content version is needed.

## Validation — 2026-10-31

- TypeScript: `npm run typecheck` clean, and 1450 tests passed. `npm run build:site` builds. `cargo check --manifest-path src-tauri/Cargo.toml --locked` is clean on 1.0.4; the Rust source is unchanged apart from the version, so its tests were not rerun here (the release workflow runs them).
- Recorder core: 41 tests.
  - The switch reads `auto`, `false` and `true`, and is unavailable, with the reason, when the ini is missing, unreadable, locked or predates the key.
  - Turning it on writes `true` to that one line and leaves every other line; off writes `false`. Nothing is written when the ini already says the value, not even the record.
  - The write is journaled, so Uninstall leaves the game folder vanilla, and a failed write is undone with no recovery left to do.
  - A Reset, a new graphics card and the Repair of a missing ini write `auto` again; a content update keeps `true`.
  - The recordings:
    - are counted by session, with the newest named;
    - only the fork's own `fg-rec-*` names count: a lookalike, a rotation with a leading zero or above 8, an empty process id, another case or a file in a subfolder is left out;
    - a file where the folder should be reads as no folder;
    - a junction Lucent won't follow marks only the row unreadable.
  - Clear removes only those names, and the folder once nothing else is in it. It refuses while XIV runs, and it asks for administrator access when only the recordings folder needs it.
  - Both actions carry over an administrator resume.
- Open folder accepts the recordings folder of the selected game folder and of every deployment, and still refuses anything else inside a game folder.
- Diagnostics: the `FG recorder:` line in each state, and the bug template's new sentence.
- Settings: 20 new screen tests.
  - The group order and the subtitle.
  - The Experimental tag on the Game patches switch.
  - The waiting line: once, at the top, and not before a deployment.
  - Reset setup as a plain button.
  - The Troubleshooting switch in each state.
  - The Recordings row with one and with two sessions, with no recordings, and after a Clear that left a player's file.
  - The Clear dialog's title, text and its busy and recovery states.
- Mutation check on the new code: 44 mutants, each a one-line change.
  - The first run killed 34.
  - Tests were then added for the gaps, and the newest-session choice was simplified to a plain name comparison. Those tests also kill the 7 gap mutants and the simplified comparison's own mutant.
  - Two survive, and both are equivalent: the activity guard in `clearRecordings` and the `deployment` guard of the Troubleshooting group each repeat a condition the state already guarantees.
- An independent review found one medium and ten low findings, all fixed except two that the rest of Settings shares (the other Clear dialogs are untested; the Game patches switch's read has no ordering guard). The medium one: a junction where `fg-recordings` should be made the switch say it couldn't read `OptiScaler.ini`; now only the row says it can't read the folder.
- On the real exe (the 1.0.4 debug build of the first commit, 2026-10-31, isolated data, a dummy game folder, content 2026.10.31 served locally, XIV closed):
  - **Install and the switch:** an install gave `FgRecorder=auto`. Settings showed the groups in order, the subtitle, the Experimental tag, the switch off and no Recordings row. Turning it on changed only that line, to `FgRecorder=true`, with line endings kept. Copy diagnostics then read `FG recorder: on` right after the auto-repair line.
  - **Recordings:** with two planted sessions and a player's file, the row read `2 sessions · 250.0 KB. Uninstall removes them.`, Open folder opened it, and diagnostics named the newest session.
  - **While XIV runs:** with a stand-in `ffxiv_dx11.exe` running, the waiting line showed once at the top and the switch, Clear…, Reset setup and Uninstall were disabled.
  - **Clear:** the dialog read `Delete 2 recording sessions (250.0 KB)?`. Clear removed the three own files, left the player's file and the folder, and said `Cleared 250.0 KB of recordings (3 files).`
  - **Reset and Uninstall:** a Reset wrote `FgRecorder=auto` again. Uninstall removed `fg-recordings` with everything in it.
  - **Registry:** the HKCU keys were the same before and after.
  - **Not run on the real exe:** the review's fixes were made after this run and are covered by the tests above. One of them changes the wording of a Recordings row with no recordings, from "Empty." to "No recordings.".
