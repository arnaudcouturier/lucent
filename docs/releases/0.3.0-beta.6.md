# Lucent 0.3.0-beta.6

- **An update no longer hides behind drift or the running game.** Home's status card picks one state by strict priority, so drift or "XIV is running" fully hid a pending app or content update, with no indication anywhere that one existed. Now, when drift or the running game is the primary card, any pending update still shows as a slim secondary row underneath it — just the version and an Update button. Still fully suppressed while something is busy, the game folder is missing, or a tier switch is pending.
- **Settings can now update the app directly.** Its "Check for updates" card gained a real Update/Skip action for an app update, reusing the same card Home shows, instead of just a status line saying to go update from Home. A content update is still actioned exclusively at Versions, which already lists every version with its own Apply/Roll back; the rail's app-update dot moved from Versions (which could never act on it) to Settings (which now can).

No content change; content 2026.10.17 works unchanged.

## Validation — 2026-10-15

- TypeScript: 701 tests passed (5 new, covering every branch of the new secondary-update logic: drift and game-running surface it, busy/folder-missing/switch-tier still suppress it, and it's never duplicated if already the primary card). Rust: 54 passed, 2 ignored. `npm run typecheck` clean on both the local candidate build and the release workflow.
- Checked by eye in the gallery: added a `drift-with-updates` state showing drift as the primary card with a content-update secondary row beneath it, and confirmed the rail dots (Home, Versions) and Settings' status-line copy match. The app-update path shares the identical code as the content-update path I visually confirmed, and is additionally covered by the new unit tests; I could not get a clean visual check of it specifically, because the gallery's app-update fixtures are now stale against this app version (noted below) — unrelated to this change.
- Nothing here touches deployment, config or GPU-tier logic, so this skips the RTX 4090 manual checklist.

## Known issue (pre-existing, not introduced here)

The gallery's app-update fixtures (`appReleaseHost`, used by several `?gallery` states and `src/core/*.test.ts` files) hardcode a fake release tagged `app-v0.2.0`. Since app-update announcement compares against the real build-time app version, every app-update gallery state now silently shows "Healthy" instead — the fake release looks older than the real app, not newer. This became visible only because tonight's version bumps pushed the real version past it; it would affect an unmodified checkout identically. Worth a fixture cleanup next time someone's in there (touches 7+ test files).
