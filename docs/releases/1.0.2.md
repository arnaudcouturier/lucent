# Lucent 1.0.2

- **The Graphics step can set the Neural Rendering preset hint for each pass.** Pass 1, Pass 2 and Pass 3 preset hints sit inside the Neural Rendering card, in a collapsed Advanced section, and the second and third show only when you have that many passes. They are the same hints OptiScaler's menu offers; their effect on the picture is unverified, so Lucent doesn't promise one. The defaults are what Lucent installs today, so nothing changes unless you pick one, and a hint applies to a new install or Reset setup. They appear once a content version offers them.
- **The Graphics step can turn Neural Rendering on or off for the character preview.** The Character preview Neural Rendering choice sits in the Neural Rendering card and is Off by default, because the model takes a lot of video memory for each open preview window. On runs it on the character, equipment and glamour previews. It applies to a new install or Reset setup, so a setup you already have keeps what it has, and it appears once a content version offers it.
- **A content update can set a few named settings in a config file you already have.** It changes only the keys it names, so the rest of the file, including your selected ReShade preset and keybinds, stays as it is. Before this, an update could only leave a config file alone, add the keys it lacked, or replace it whole.
- **Nothing happens until a content version uses these.** No content version needs this release yet. The rest of the setup and every other screen are as they were in 1.0.1.

## Validation — 2026-10-24

- TypeScript: `npm run typecheck` clean and 1268 tests passed. `cargo check --manifest-path src-tauri/Cargo.toml --locked` clean on 1.0.2; the Rust source is unchanged since 1.0.1, so its tests were not rerun.
- Setting keys on update: covered by 14 tests of the update and the INI helper and 8 of the manifest validator: the listed keys change and every other byte of the file stays (BOM, line endings, comments); a key the file lacks is added; a file that already holds the values is not rewritten; it combines with add missing keys; a selected preset moves off a removed one however the path is written, and a different preset or a missing key is left alone; a key is set once, so a version that carries it again does not override the player's later choice; replace ignores it; a locked config fails the update and a config that is not UTF-8 text is left as it is; a rollback restores the file; and an update that drops a preset, remaps the selection and sets the toggles in one go leaves the player's other keys unchanged, with or without an edited copy of the dropped preset. The tests that check the new behaviour fail without the change. Separately, by hand, the 1.0.1 app's own validator parsed a manifest that carries the field and dropped it without an error.
