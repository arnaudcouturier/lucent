# Full-app review, 2026-10-23

Branch `review/quality-pass`, based on `main` at 60608ad (app 0.3.0-beta.8). The yardstick is
`docs/decisions.md` plus `docs/release-checklist.md`. GitHub issue #1 ("Spec: Lucent 1.0") was last
edited on 2026-10-14 00:03, before the scope reset, and still describes the Custom profile, the
profile switcher on Home and the ⋯ menu. It is stale; this review did not use it and did not edit it.

Status legend for every finding: **open** (not yet verified or fixed), **fixed** (with the test or check
that proves it), **rejected** (false positive, or decided in `decisions.md`), **human-only** (needs the
maintainer's machine, hardware or a product call).

## Result

Eight read-only reviewers filed 80 findings (1 high, 28 medium, 51 low). Each was read against the code before it
was fixed. Outcome: **74 fixed**, **3 rejected** after checking (RSF-1 and RSP-9 / CFG-5: both tested on this machine and not
reproduced), **2 human-only** (CORE-7, and CFG-4 whose patch is written out below but goes live to players on merge)
and **1 by design** (RSF-9). Two more were found by driving the app in a browser and fixed (UI-12: muted text on a selected option
at 4.48:1; UI-13: two rail rows highlighted while Mods is open during setup). Of the 7 spec gaps, 4 are fixed
(GAP-6 to GAP-9), 1 was rejected (GAP-5), 2 are human-only (GAP-1, GAP-2), GAP-3 was built after the review, and GAP-4 was declined (see below).

The one high finding, **DEP-1**: Uninstall could delete a file the player had put at a path Lucent once created
(a `winmm.dll` dropped in while Lucent was Disabled, or a file re-added after an update stopped deploying it).
Ownership is now decided from the path's newest journal entry, with tests for both scenarios and for the interrupted
and resumed uninstall.

After the fixes: `npm run typecheck` clean; `npm test` 1,111 tests in 72 files (858 in 58 before); `cargo test
--locked` 93 passed and 3 ignored on purpose (71 and 2 before; the new one is `exe_running_elsewhere_child`, a helper
only its parent test launches); the release build (`npm run tauri -- build --ci --no-bundle --target
x86_64-pc-windows-msvc -- --locked`) exits 0.

The new parsing code was also run read-only against the maintainer's real files (printing only counts and public repo
addresses): `dalamudConfig.json` has 3 repo entries, all with an `IsEnabled` key and all read as enabled (so MODS-7
changes nothing there); `settings.json` reads and writes normally; the real deployment record (170 stamps, 196 journal
entries, content 2026.10.21) still validates under DEP-8's stricter check and without the new `readOnly` field.

The UI audit (overflow, clipped text, overlap, accessible names, targets, WCAG AA contrast, console) was re-run on the
final code and was clean each time: at 880×600 on nr240Hdr (every first-run step, every section, the Reset and

(`?gallery`, about 100 app states: first-run steps, XIV running, drift with updates pending, app update, updating,

## Findings by area

### CORE — orchestration and lifecycle (`src/core/core.ts` and neighbours)

All entries below are the reviewer's claims, not yet verified by a second read.

- **CORE-1 · medium · bug · fixed** — `src/core/core.ts:1457-1462`. `uninstallApp` calls
  `platform.exitAndRemove` before it sets `notice`, and the real port ends the process there
  (`platform.rs:1609`, `std::process::exit(0)`), so the "remove the XIVLauncher add-ons yourself" note
  is never shown. With XIVLauncher open during App uninstall, its two Lucent add-ons stay and a later
  game launch runs a missing exe.
- **CORE-2 · medium · spec-divergence · fixed** — `core.ts:1459-1460`, `selfInstall.ts:61-65`,
  `deployment.ts:533`. App uninstall deletes all of `%LOCALAPPDATA%\Lucent`, including `Backups\`. A
  player who chose "restore the game to vanilla" (readable copies kept by design) loses those copies,
  the only copy of their old setup, when they later uninstall Lucent. The uninstall window says
  nothing about it. Also `notify()` creates `HKCU\Software\Classes\AppUserModelId\io.github.arnaudcouturier.lucent`
  and `removeSelfInstall` never deletes it ("nothing left behind").
- **CORE-3 · medium · bug · fixed** — `core.ts:1451-1454`. The "keep game files" branch of
  `uninstallApp` calls `restoreAutoHdrPreference` for every complete record without the
  `isGameFolder` skip the restore branch has (`:1444`). It throws "Game folder is missing"
  (`files.rs:245`) when a record's folder is gone or on an unplugged drive, so unticking "Restore the
  game folder" aborts and Lucent cannot be uninstalled.
- **CORE-4 · medium · bug · fixed** — `core.ts:1434-1465`. Settings → Apps starts a second
  `Lucent.exe --uninstall` process with no single-instance guard. If the main window is open from the
  installed exe, `rmdir /s /q` (`platform.rs:1587`, errors hidden) cannot delete the locked exe, still
  deletes the shared WebView2 data folder, and the running window then recreates `settings.json` and
  `lucent.log`.
- **CORE-5 · medium (low confidence) · bug · fixed (known limit: HKCU stays the elevated account’s)** — `core.ts:277-288`. After a UAC relaunch under a
  different administrator account, the proxy remaps only LocalAppData and Pictures. Documents, AppData
  and HKCU still resolve to the administrator's profile, so App uninstall looks for add-ons, shortcut
  and Settings → Apps entry in the wrong profile (and `removeUninstallEntry` treats "missing" as
  success), and an elevated install or Reset cannot find `FFXIV.cfg`, so the frame cap falls back to
  the primary monitor. Unchecked: how common the standard user plus administrator credentials case is.
- **CORE-6 · low · bug · fixed (notice)** — `core.ts:1375-1376`. After an administrator relaunch, Launch XIV
  spawns the launcher with the elevated token (`platform.rs:1064`), so XIV and Dalamud run elevated.
- **CORE-7 · low · security · human-only (hardening, maintainer’s call)** — `core.ts:901-905`, `xivLauncher.ts:57-60`. With `runAsAdmin`,
  Lucent registers its exe (a user-writable path) as an elevated XIVLauncher add-on that runs at each
  game launch and close. A same-user process that swaps the exe gets a UAC prompt that looks expected.
- **CORE-8 · low · bug · fixed** — `core.ts:790-798, 1343-1346`. `applyReset` (Reset and tier switch)
  never calls `refreshVersions` or `refreshUpdateCheck`; `finish()` rebuilds the card with
  `update: null` and the stale module-level `deployedDrift`. After a tier switch `state.versions` is
  for the old tier until the next Scan; after any Reset a pending content update row disappears and
  drift found by the post-Reset health check is not shown.
- **CORE-9 · low · bug · fixed** — `core.ts:963`. A later Scan in the same administrator-relaunched
  process runs `takeElevationResume` again; the resume file is consumed, so `playerUserSid` becomes
  undefined and Auto HDR is later written for the elevated account (`deployment.ts:596`). Only with a
  different administrator account.
- **CORE-10 · low · bug · fixed** — `core.ts:431, 948, 1350, 1378`. `launchingUntil` is set only after
  `startProgram`, so the one-second `refreshGameRunning` poll can clear `launching` early and a second
  click starts a second launch.
- **CORE-11 · low · bug · fixed** — `src/core/settings.ts:43`. `readSettings` turns any read error
  (including a transient sharing violation) into defaults, and the next `writeSettings` persists them,
  losing `skippedContent`, `launcher` and a hand-picked `gameFolder`.
- **CORE-12 · low (low confidence) · bug · fixed** — `src/core/diagnostics.ts:52-86`. Diagnostics omit
  the stored first-install choices, launcher and auto-repair state, but print Expected and Actual for
  every file (about 32 KB for ~170 files) plus 300 lines of `OptiScaler.log` with absolute paths and
  the Windows account name. That can pass GitHub's 65,536-character issue-body limit.

Checked and sound (reviewer): operation lock and `coordinated` reload; resume-file validation;
XIVLauncher add-on edit (refuses while running, keeps other entries, atomic write); launcher and game
detection; `openLink` HTTPS-only in TypeScript and Rust; status card precedence; activity-log
serialisation; `busy` released in `finally`; self-install ordering and update, rollback and skip
bookkeeping.

### MODS — Starter set (`src/core/starterSet.ts`, `src/ui/ModsScreen.tsx`)

Reviewer's claims, not yet verified by a second read.

- **MODS-1 · medium · security / spec-divergence · fixed** — `starterSet.ts:331-336`, `files.rs:761-766,
  773-792`, `platform.rs:1082-1096`. `assertFetchable` (HTTPS only, no Heliosphere) runs on the first URL
  only. Both reqwest clients keep the default redirect policy with `https_only` unset (reqwest 0.13.5
  follows any http or https hop). The host test also misses a trailing-dot name such as
  `repo.heliosphere.app.`. A plugin's `DownloadLinkInstall` that 302s to Heliosphere breaks
  decisions.md ("Nothing is ever fetched from a heliosphere.app address"); a hop to `http://` lets an
  on-path attacker swap a zip that has no hash, and the same applies to the `repo.json` fetch. Direction:
  a per-hop redirect policy that requires https and refuses Heliosphere hosts (trailing dot stripped),
  keeping redirects since GitHub release assets need them.
- **MODS-2 · medium · bug / spec-divergence · fixed** — `starterSet.ts:176,188,401-406,461-471`,
  `ModsScreen.tsx:17`, `core.ts:873-885`. Repo decisions at write time use the scan taken when the screen
  opened. `closedGuard` never rescans and `seedPlugins` re-reads the config only when `newRepos` is
  non-empty. If the player removes or disables SeaOfStars in `/xlsettings` while the screen stays open,
  Penumbra is placed with an `InstalledFromUrl` Dalamud will not load, the report says "Added", and the
  consent panel named repos from the old scan. Direction: once guarded, re-derive each repo's present and
  enabled state from the freshly read config and skip or re-confirm plugins whose repo changed.
- **MODS-3 · low · bug · fixed** — `starterSet.ts:475`, `core.ts:890-893`. The per-plugin `guard()` sits
  outside the try block. If XIV or XIVLauncher starts after repos were appended and earlier plugins
  placed, it throws out of `seedPlugins`, the outcome is discarded, the UI shows only "Close XIV" and the
  scan is not refreshed (placed plugins still read "Not installed", added repos go unreported).
- **MODS-4 · low · bug · fixed** — `files.rs:797-806`, `platform.rs:1087-1096`. No size cap: `download_file`
  streams to disk and `fetch_text` buffers the whole body; `read_timeout` is per chunk, so a steady stream
  never ends. `ZIP_LIMITS` apply only after the download, so an untrusted repo can fill `%LOCALAPPDATA%`.
- **MODS-5 · low · bug · fixed** — `ModsScreen.tsx:57,62-68,96`, `App.tsx:23`. The report is local
  `useState` in `PluginsGroup`; leaving the section during or after Add loses the "Left out" reasons and
  the "Then set up" lines (the only place Browsingway's overlay-URL step is explained), although
  `starterSet.result` keeps them. Direction: render from `starterSet.result`, clear on the next Add.
- **MODS-6 · low · spec-divergence · fixed** — `ModsScreen.tsx:165-181`. decisions.md says that with
  `ModDirectory` unset the mod rows say "Set Penumbra's mod folder first". The code shows only a group
  note and still renders **Get on Heliosphere**, and the note says "set one in Penumbra's Settings" even
  when Penumbra is not installed.
- **MODS-7 · low · bug · fixed** — `starterSet.ts:85`. `IsEnabled !== false` treats a repo entry with no
  `IsEnabled` key as enabled; Dalamud's field is a plain bool that defaults to false. A hand-edited entry
  shows the plugin as available and Lucent places one Dalamud will not load.
- **MODS-8 · low · bug · fixed** — `starterSet.ts:27`, `core.ts:277-286`, `xivLauncher.ts:14`. The
  `envFolder` proxy remaps only LocalAppData and Pictures after a relaunch as another administrator, so
  `dalamudPaths` reads that administrator's `AppData\Roaming\XIVLauncher` (same root cause as CORE-5).
- **MODS-9 · low · bug · fixed** — `files.rs:25-33,64-69`, `starterSet.ts:468`. `writeText` on
  `dalamudConfig.json` goes through `commit`, which calls `clear_readonly` and never restores it; a player
  who set read-only to stop Dalamud overwriting the file loses that silently.
- **MODS-10 · low (low confidence) · bug · fixed** — `starterSet.ts:481-497`. The "appeared since the
  scan" check turns any `listFolders` failure into an empty list, and the failure cleanup then removes
  every pre-registered destination path including files that existed before. Needs a listing error plus an
  existing same-version folder; unclear whether `replace:false` fails before any overwrite in all cases.

Checked and sound (reviewer): `addThirdRepos` (BOM, CRLF, indents, one-line files, empty list, disabled
or duplicate entries, other shapes, bracket-containing strings, read-back compare); the Rust zip planner
(symlinks, `:`, device names, trailing dot or space, absolute paths, `enclosed_name`, `create_new`, size
caps) with the TypeScript re-check; Penumbra detection against 1.7.2.1; Heliosphere's `manual` flag keeps
it out of the fetch path; the consent dialog is the only UI path to `addPlugins`; `validateStarterSet`
and the `InstalledFromUrl` / `OFFICIAL` handling match decisions.md.

### UPD — updates, manifest and publishing (`appUpdate.ts`, `versions.ts`, `scripts/`, workflows)

Reviewer's claims, not yet verified by a second read.

- **UPD-1 · medium · bug · fixed** — `core.ts:610-617,911-922,1198-1205`. When the releases fetch fails,
  `refreshUpdateCheck` keeps `state.appUpdate` and `updateApp` installs it without re-checking the
  channel. A Beta player sees "beta.9 available", switches to Stable, GitHub's unauthenticated API limit
  returns 403 while github.com downloads still work, and Update installs a pre-release on Stable. The
  content side is guarded (`versionSource` filters `onChannel`, `core.ts:350`) but fails with a
  misleading "no longer published". A Skip made while the manifest fetch fails is not reflected because
  `refreshAnnouncement` (`core.ts:663`) does not pass `state.manifest`.
- **UPD-2 · medium · security · fixed (narrows the threat; a hash outside the API response would close it)** — `appUpdate.ts:54-58,111-139`, `files.rs:773-812`. The app
  update's download URL and SHA-256 both come from the same GitHub API response; `browser_download_url`
  has no https, host or path check and `size` has no cap. A TLS-inspecting proxy or rogue root CA (reqwest
  uses native-tls) can return a matching URL and digest, and Lucent renames the result over `Lucent.exe`
  and relaunches it. Direction: pin the URL to
  `https://github.com/arnaudcouturier/lucent/releases/download/app-v<ver>/Lucent.exe`, cap the size, and
  optionally publish the expected hash outside the API response (decisions.md rejects signing, not a hash anchor).
- **UPD-3 · medium · bug · fixed** — `platform.rs:1080-1097`, `Cargo.toml:22`, `appUpdate.ts:8`. The update
  check downloads uncompressed multi-MB payloads (the shared `/releases?per_page=100` list carries every
  content asset, about 1,132 now, plus the 1.57 MB manifest) under a 20 s total timeout with no gzip.
  Reviewer's arithmetic: 2.7–3.8 MB per check, about 1.1–1.5 Mbps needed; below that the app check times
  out and no app update is ever announced. The list is also unpaginated, so 100+ content releases newer
  than the latest app release would push the app release off page 1. Not measured on the real response.
- **UPD-4 · medium · bug / spec-divergence · fixed (repair refuses; refreshing the installed exe from a portable copy is human-only)** — `appUpdate.ts:112`, `selfInstall.ts:54-58`,
  `core.ts:904`, `autoRepair.ts`. An app update replaces only the running exe; the XIVLauncher add-on
  points at the installed exe, and no repair, health or uninstall path compares the deployed content's
  `minAppVersion` with the running app. An older installed beta.7 add-on running a headless repair would
  write the literal `{Pictures}\FFXIV Screenshots` as `SavePath` (`userFolders.ts` does not exist in
  beta.7). Direction: refuse or warn when the app is older than the deployed `minAppVersion`; make an
  update from a non-installed copy refresh the installed exe.
- **UPD-5 · low · bug · fixed** — `scripts/publish-content.ts:55-58`. A content id only has to be a real
  calendar date. A typo such as `2026.11.22` publishes as an immutable id; `announcedContent` uses
  `v.id > current`, so every later correctly dated version is never announced to people on it.
- **UPD-6 · low · spec-divergence · fixed** — `src/shared/manifest.ts:530-533`,
  `scripts/publish-content.ts:130-135`. Nothing ties a Stable content version's `minAppVersion` to a Stable
  app. Promoting 2026.10.21 (min `0.3.0-beta.8`) before a Stable 0.3.0 exists hides it from Stable players.
- **UPD-7 · low · bug · fixed** — `scripts/prepare-fork-candidate.ts:94,106`. The `isAbsolute(outputRoot)`
  guard is dead (already resolved) and line 106 runs `rm(outputRoot, { recursive, force })`; `--output`
  pointing at a folder holding the verified zips or sources deletes them before extraction.
- **UPD-8 · low (medium confidence) · bug · fixed** — `.github/workflows/release.yml:84`,
  `appUpdate.ts:57`. `--generate-notes` bodies are shown one raw line per `<li>` ("## What's Changed",
  "**Full Changelog**…"); with direct merges that is the whole note and `docs/releases/*.md` is unused.
- **UPD-9 · low · bug · fixed** — `src/core/credits.ts:15-17`. The deployed version's components and GPL
  source tags come only from the live manifest; offline or for an unpublished version Credits has no list
  although `deployment.cachedVersions[0]` holds it.
- **UPD-10 · low (low confidence) · bug · fixed (warning only)** — `publish-content.ts:337-342`, `shader-usage.ts:44`. The
  shader collision gate keys on the full path but ReShade resolves includes by basename; every version
  already ships `reshade.fxh` and `ffxiv_common.fxh` twice with different hashes. Probably intended, a
  latent gate gap rather than a divergence.

Checked and sound (reviewer): `release.yml` (strict tag regex, tag via `$env:`, `persist-credentials:
false`, token only in the publish step, version match, tests before publish) and `pages.yml`;
`performAppUpdate` (hash checked on the download and on the prepared copy, rollback branches);
version logic (`compareAppVersions`, `needsNewerApp`, channel filtering, never a downgrade on leaving
Beta, pin, skip and rollback with three cached snapshots); `manifest.json` round-trips byte-identically
through the validator, no size or release mismatches among 1,132 hashes, `minAppVersion` monotone;
publisher refusals; content downloads size and SHA-256 checked before the game folder changes.
